# ELCA Toronto Phase 1 UI Prototype — Implementation Plan (Index)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Phase 1 front-end prototype of the ELCA Toronto website: 9 routes × EN/KO, design tokens, accessible UI components, demo forms, and a mock-data content layer that can later be swapped for Sanity.

**Architecture:** Next.js 16 App Router with `cacheComponents`, all public routes under `app/[locale]` (next-intl, always-prefixed). Pages call a server-only Content Repository (`lib/content`, functions marked `'use cache'`) that reads TypeScript mock documents shaped like future Sanity documents (`{ en, ko }` localized fields) and returns locale-resolved ViewModels. Components never import data; visual decisions live only in `app/globals.css` tokens and `components/ui`.

**Tech Stack:** Node 24, Next.js 16.4.0, React 19.3.0, TypeScript 5.9, Tailwind CSS 4.3 (Turbopack loader), next-intl 4.14.9, zod 4.6.7, lucide-react 1.56.0, @portabletext/react 8.0.1, Vitest 5.0.4, Playwright 1.64.0 + @axe-core/playwright 4.13.0.

**Spec:** [`docs/specs/`](../specs/) — start at [`00-overview.md`](../specs/00-overview.md). Executors read the spec files referenced by each task.

## Global Constraints

Every task's requirements implicitly include this section.

- **Node 24 only.** `.nvmrc` contains `24`; `package.json` `engines.node` is `">=24"`. The machine's nvm default stays Node 20 for other projects — never run `nvm alias default`. Agent shells do not persist state, so **prefix every shell command with** `source ~/.nvm/nvm.sh && nvm use >/dev/null && ` (commands in this plan omit the prefix for readability).
- **Exact dependency versions** (install with `--save-exact`): next 16.4.0, react 19.3.0, react-dom 19.3.0, next-intl 4.14.9, zod 4.6.7, lucide-react 1.56.0, @portabletext/react 8.0.1, @portabletext/types 4.0.2, server-only 0.0.1; dev: tailwindcss 4.3.3, @tailwindcss/turbopack 4.3.3, typescript 5.9.3, eslint 9.39.5, eslint-config-next 16.4.0, @types/node 24.19.2, @types/react 19.3.0, @types/react-dom 19.3.0, vitest 5.0.4, @playwright/test 1.64.0, @axe-core/playwright 4.13.0. **No other runtime dependencies** (no UI kits, no tailwind-merge, no date libs).
- **Next.js config:** `cacheComponents: true`; `partialPrefetching` **off** (with it on, unknown `[slug]` paths return HTTP 200 instead of 404 — verified). No `dynamicParams` export anywhere (incompatible with cacheComponents).
- **Current time:** never call `new Date()` (no args), `Date.now()`, or `Math.random()` in a Server Component render path. Current-time logic lives only inside `'use cache'` repository functions or in Client Component effects/handlers. `new Date(isoString)` for formatting is fine.
- **Locales:** `en` (default) and `ko`, URL prefix always (`/en/...`, `/ko/...`). Internal links use `Link` from `@/lib/i18n/navigation` with locale-less hrefs (`/about`, `/contact?topic=mentor`, `#apply`). Never hardcode `/en/`.
- **Copy:** user-visible text comes from `messages/{en,ko}.json` (UI labels) or `data/mock` (editable content). Only `app/[locale]/ui-lab` may hardcode demo text. `messages/en.json` and `messages/ko.json` must have identical key sets (unit-tested).
- **Data boundary:** files under `components/` never import `@/lib/content/*` or `@/data/*`. Pure helpers in `lib/content/helpers/*` may be imported by client components. Every `lib/content/*.ts` (non-helper) file starts with `import 'server-only';`.
- **Styling:** colors only via theme tokens (`bg-primary`, `text-muted`, …). No hex values and no arbitrary `px` values in `className`; use the Tailwind scale or `rem` inside arbitrary values. Radius tokens `rounded-card` (8px) / `rounded-button` (6px). No default shadows; only `shadow-float` on floating elements (dropdown, dialog, floating buttons).
- **Breakpoints:** Tailwind defaults only — `sm` 640, `lg` 1024, `xl` 1280. Do not use `md`.
- **Motion:** transitions only on hover/focus/menu/accordion, `duration-150` or `duration-200`. Global CSS disables transitions and smooth scrolling under `prefers-reduced-motion: reduce`; the carousel never autoplays under reduced motion.
- **Accessibility:** one `h1` per page; no skipped heading levels; landmarks `header`/`nav`/`main#main`/`footer`; icon-only buttons have `aria-label`; touch targets ≥ 44px (`size-11` / `min-h-11`); focus visible via global `:focus-visible` outline (`secondary`, white inside `.on-dark`).
- **Flags:** render `<FlagBadges flags={item} />` next to any data with `isSample` / `needsReview`.
- **Demo forms:** validate with zod schemas in `lib/validation/forms.ts`, show a "Demo" status on success, never call `fetch` or any network API.
- **Images:** `next/image` with `images.unsplash.com` remote pattern only; every image sits in a fixed aspect-ratio box (`ImageFrame`) or has explicit `width`/`height`.
- **Commits:** one commit per task minimum, conventional-commit style, ending with:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```
- **Next.js docs:** this Next.js version differs from older training data. When unsure about an API, read `node_modules/next/dist/docs/` before writing code (see `AGENTS.md`, which `next dev` writes into the repo; commit it).

## Review Focus

Failure modes the spec implies but no feature test would naturally exercise. Each has a pinning test in the owning task.

1. **Missing or blank Korean translation** → falls back to English, never renders an empty string. Pinned in Task 4 (`localize` treats `''`/`[]` as missing) and Task 6 (mock integrity: every `ko` that exists is non-blank).
2. **Very long names/companies at 375px** → wrap inside the card, no horizontal page scroll. Pinned in Task 6 (mock mentor `taeyoung-moon` has a 70+ char company) and Task 25 (overflow check on every route at 375/768/1280).
3. **Hand-edited query strings** (`?category=<script>`, `?topic=unknown`, `?category=WORKSHOPS`) → ignored, default state shown, no crash. Pinned in Task 12 (`parseEnum` unit tests) and Tasks 20/22 (E2E).
4. **Navigating away while an overlay is open** (tap a link inside the mobile drawer, or press browser Back with a dialog open) → overlay count returns to 0 and the floating buttons reappear; page scroll is unlocked. Pinned in Task 13 (E2E).
5. **Whitespace-only input and double submission** of demo forms → whitespace is trimmed and rejected as `required`; a second submit right after the demo notice (double click) keeps the notice and does not flash `required` errors on the reset form. Pinned in Task 12 (unit: trimming) and Task 20 (E2E: both).
6. **An event happening right now** (`startsAt < now < endsAt`) → treated as upcoming (registration still shown). Pinned in Task 5.

## Execution notes

- E2E runs against a **production build** (`npm run build && npm run start -p 3100`) started by Playwright with `NEXT_PUBLIC_ENABLE_UI_LAB=1`. A single `npm run test:e2e -- tests/e2e/<file>` rebuilds (≈1 min); that is expected.
- Playwright projects: `desktop` (1280×800) and `mobile` (375×812, touch). Tests that only make sense on one viewport skip themselves with `test.skip(testInfo.project.name !== 'desktop', …)`.
- If Playwright reports a missing browser, run `npx playwright install chromium` once.
